# app-icon-studio

把产品概念变成清晰、可复用的应用图标。默认交付 1024 × 1024 直角正方形源图：背景铺满画布，无圆角遮罩、外部留白、厚边或外投影。主体内部可以有圆弧和柔和造型；直角约束只作用于画布。

## 1. 确定输入与产物

先看用户提供的参考图、已有图标和产品信息。提取一个核心意象、材质、带色号的配色和 2–3 个细节。没有指定风格时，使用可爱玩具质感；保留用户明确指定的风格。

缺少产品用途且无法推断时，只问一个关键问题。其余可逆选择自行推进，不因默认参数再次确认。

确定本次产物：默认一张正方形源图；只要提示词时不生成图片；要求候选时分别生成；要求分层时读取 [Icon Composer 素材规范](references/icon-composer.md)。不要把默认数量扩成图标套装。

创建本次独立输出目录。沿用宿主或项目的输出约定；无约定时使用当前工作目录下的新目录。保留原图和旧候选，不覆盖现有应用资源。

## 2. 组装提示词

读取 [输入与命令](references/commands.md)，保存 `brief.json`。用 `scripts/icon_tools.py prompt` 生成 `prompt.txt`；固定结构来自 [提示词模板](assets/prompt-templates.json)。按序保留画布约束、主题描述和固定收尾。

检查主题、材质、细节是否与固定约束矛盾。自由文本不能要求给整个图标添加圆角、白色外框或展示底座。若用户明确改变产物规范，优先执行用户要求，保存本次独立提示词并记录偏离默认值；不要修改已安装模板。

前景模式使用透明画布和简洁基础形状，不沿用整图的满铺背景。图像工具的透明参数必须与模式一致：源图关闭透明，前景打开透明。

## 3. 生成或修改

检查宿主已有图像生成与编辑能力，遵循相应工具或图像 Skill 的调用规范。直接使用现成能力，不要求用户重新提供密钥，不自行增加外部服务或启动另一个宿主进程。

生成请求必须实际调用图像工具。若没有图像能力，交付已保存的提示词并明确标记图片未生成；不要用代码画简单图形冒充已完成的生成图。

修改已有图标时先查看原图，将原图作为编辑参考。保留主体身份、布局和未要求改变的部分。保真度取决于工具；不要承诺生成模型能逐像素保留品牌标记。

默认每个候选独立生成一张图，避免把网格拼图当成最终图标。选定参考或生成结果后，保留工具返回的原始图像，再制作交付副本。

## 4. 检查与修复

用 `scripts/icon_tools.py check` 检查每张最终 PNG 的尺寸、格式与透明度。先发现可用的 Python/Pillow 环境；缺少依赖时按 [输入与命令](references/commands.md) 恢复，不把缺少检查工具写成通过。

查看图片全尺寸及 64 像素、32 像素预览。确认无预制圆角、外框、留白或外投影；主体可辨认；细节未堆叠；文字与水印未出现。主体内部阴影可以保留，围绕整张图标的展示投影必须去掉。

有参考图时并排比较轮廓、比例、颜色与材质。分层素材还要在明暗底色上检查透明边缘，并按相同画布尺寸叠放检查位置；脚本通过不能替代这些目视检查。

发现问题时只修复对应缺陷，最多进行两轮自动返修。仍不满足要求时交付可用结果并列出具体缺陷，让用户选择方向；不要无限生成或宣称验收通过。

## 5. 交付与停止

正常交付包括 `icon.png`、`brief.json`、`prompt.txt` 和简短 `qa.md`。原图与预览分开命名；预览不得覆盖源图。若只有提示词，省略图片并明确生成尚未执行。

在 `qa.md` 区分脚本检查、目视检查、用户审美确认与原生导入状态。展示实际图像并链接文件，简述已通过的检查和仍存在的限制。

透明前景素材、已保存的 `.icon` 工程、应用内运行和商店发布是不同完成层级。没有执行的层级不得声称完成。用户没有要求时，完成素材交付即停止，不修改项目、不提交上架。
