# 开发机磁盘清理

先确认实际占用，再识别可重建内容，最后按已有授权清理并测量真实回收量。目录名称不是删除依据，`build`、`dist` 和 `artifacts` 可能包含源码、签名配置、发布文件或必须保留的证据。

## 1. 只读调查

确认要检查的磁盘或目录。默认检查当前 Mac 的用户目录；用户指定外接磁盘时以该磁盘为准。记录对应文件系统的可用空间：

```bash
df -h "$HOME"
du -xhd 1 "$HOME/Library/Developer" 2>/dev/null | sort -hr | head -20
du -xhd 1 "$HOME/Documents" 2>/dev/null | sort -hr | head -20
```

不存在的目录跳过，权限不足应记录；不为完成调查申请整盘访问权限。先查看一级占用，只对大目录继续下钻，避免反复扫描整个用户目录。

按环境检查常见占用：

| 位置 | 调查重点 | 清理边界 |
| --- | --- | --- |
| Xcode DerivedData | 项目归属、运行中的 App、构建与索引任务 | 只清理已确认闲置且可重建的具体目录 |
| Xcode DeviceSupport | 调试符号与当前设备系统版本 | 明确下次连接可能重新下载或生成 |
| CoreSimulator、XCTestDevices | 设备状态、数据、快照和 APFS 克隆 | 用系统管理工具逐项处理；不整体删除设备根目录 |
| SwiftPM、Gradle 缓存 | 依赖重下载成本、活跃构建 | 只处理授权的缓存，不删除仓库和本地源码 |
| Android AVD | 模拟器定义、系统镜像、用户数据和快照 | 用户数据与快照不是普通缓存，重置必须另有明确授权 |
| 项目依赖与构建目录 | 版本跟踪、忽略规则、本地配置、发布文件 | 不凭名称统一删除，不运行全仓库清理命令 |
| Application Support、Containers | 应用数据库、账号、素材和用户资料 | 不能当作缓存处理 |

## 2. 制定具体清单

对每个候选记录绝对路径、测得大小、用途、可重建依据、活跃状态和删除影响。判断时：

1. 核对版本管理中的已跟踪文件、未提交改动和被忽略的本地配置。保留 `.git`、`.jj`、工作区、原始素材、密钥和签名资料。
2. 查询进程及打开文件；检查正在运行的 App 是否来自候选目录。状态不明确时保留，不终止无关进程。
3. 将归档、安装包和验收证据单独列出；它们即使能重新生成，也不自动属于缓存。
4. 报告候选大小与删除影响。APFS 克隆、快照和共享块会使 `du` 与真实可回收空间不同，不承诺按目录大小等额回收。

## 3. 在授权范围内清理

仅当用户已授权清理相应候选时执行；已有明确授权可直接沿用，不重复确认。用户只要求“看看”时保持只读。新的数据重置、卸载或超出清单的删除须先说明并取得授权。

执行前重新检查路径、符号链接和进程状态，防止调查后目录用途已变化。优先使用环境提供的定向清理工具，并先检查其当前帮助与预览能力：

```bash
brew cleanup --dry-run
xcrun simctl list devices
```

仅在已安装对应工具时运行。管理工具的清理范围也必须与授权清单一致；“不可用模拟器”仍可能有用户数据。不要全局终止构建进程，不使用通配符清空整个开发目录，不根据文本列表直接拼接删除命令。

没有可靠可重建依据、路径越界、仍被使用或操作范围不明时停止该项，继续处理独立且已确认的候选。报告跳过原因。

## 4. 验证结果

再次读取同一文件系统的可用空间，并检查已处理目录及应保留文件。列出实际处理路径、失败与跳过项、前后可用空间和观察到的差值。其他进程同时写入会影响差值，应注明测量边界。

迁移任务默认复制重要资料并保留源文件。不要将“只迁移重要文件”解释为允许删除旧电脑上的资料。
