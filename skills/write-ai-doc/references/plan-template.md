# 方案：填写主题

状态：草稿

## 背景

说明问题及相关现有行为，链接已核实的代码或历史记录。计划新增的路径明确标为拟新增。

## 目标与非目标

说明预期结果、明确不做的事项、范围边界和约束。

## 设计方案

说明推荐行为及受影响模块。仅在相关时补充 API、兼容性、持久化和发布安排。

## 备选与决策

记录重要备选、取舍和选择理由。区分建议、已确认和用户已委托的决策，并注明讨论依据。

## 验收与验证

| 编号 | 验收标准 | 必要验证条件 | 验证方法与环境 | 所需证据 |
| --- | --- | --- | --- | --- |
| AC-01 | 可观察的结果 | 必须 / 非必须及理由 | 测试、操作或检查 | 输出、截图录屏或状态回读 |

编号贯穿实施与交付，不随结果重新排序。新增项使用新编号，删除或替换项保留决策依据。必要检查缺失不能视为验收通过。

## 审核要求

说明独立审核是否为交付必要条件、审核范围及理由。重要功能默认需要独立审核；小修可自检并注明未独立审核；数据迁移、权限、支付和公共 API 必须独立审核关键边界。只保留适用于当前任务的要求。

## 待确定事项

列出未解决决策及解决方法；没有剩余问题时写“无”。
