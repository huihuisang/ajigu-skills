# 小红书送码监控

监控一篇小红书笔记的评论区 + 私信，自动完成「评论引导私信 → 私信发码 → 失效补码」的完整闭环。

## 前置条件

- 可访问小红书网页的内置浏览器。先检查现有登录态：已登录就直接复用；未登录或会话过期时，请用户在已打开的浏览器窗口中自行登录，然后继续。不要索取或读取用户密码、Cookie、会话令牌。
- 目标笔记 URL。先使用用户给出的链接或当前已打开的笔记页；如果裸链接触发 404/安全验证，请用户在已登录的浏览器中手动打开目标笔记。只有手动打开仍不可行时，才请用户补充含 `xsec_token` 的分享链接。
- 兑换码 CSV 文件：每行 `CODE,https://apps.apple.com/redeem?ctx=offercodes&id=<APPID>&code=CODE`。启动整套流程时需要。
- 用户自己的小红书 uid 从已登录页面探测，不要要求用户提供。

用户说「启动」「开始送码监控」「继续监控」时，按已确认的配置运行整套流程。启动或恢复整套送码监控即授权其评论回复和私信发送，无需逐项确认。用户明确要求「只查看」「只汇报」或限定某一环节时，按指定范围执行。

## 需要向用户确认的参数

| 参数 | 说明 | 示例 |
|---|---|---|
| 码表 CSV 路径 | 每个码一行，从第一行顺序取 | `~/Downloads/表格/OfferCode_XXX.csv` |
| 感谢语模板 | 发码后发送 | 原样发送，一字不改 |
| 评论引导语 | 默认 `私我～` | 可自定义 |
| 使用说明模板 | 用于回复兑换问题，可用右侧示例作为默认 | `App Store 右上角头像点击，上拉找到兑换代码使用` |

复用本笔记已有的 URL、码表路径和模板。启动前确认码表可读写、有未用码，且感谢语已配置。缺少必填配置或码表为空时，一次列出缺项并暂停整套流程的发送；可先只读巡查并汇报，不能把仅回复评论算作启动成功。

## 快速开始：执行一轮监控

一轮必须检查 A 私信处理和 B 新评论者引导，按 A → B 执行。先读 references/tech-details.md。某一环节无待办时继续下一环节。每轮分别汇报私信发码、补码、兑换答复、评论回复数量，以及余码和任何阻塞；未检查私信时明确说明。

### A. 私信发码

1. 打开 `/chat` 页，检查「陌生人消息」折叠夹（未回复过的陌生人会被小红书折叠在这里，主列表看不到）和主列表中带未读角标的 c2c 会话。
2. 可以先从列表记下未读会话，但每次只打开一条。打开后立即核对活动来源、最新诉求和右侧的发码记录，在当前会话完成发送、验证和码表更新，或记录跳过原因及待办，再打开下一条。打开会话会清除未读标记，禁止先批量点开再回头处理。按以下规则判断：
   - **私信只有问候、表情或「dd」等简短内容**：先按同一账号核对目标笔记的评论。如果该账号明确求过码，且已收到作者「私我～」的引导，把这次私信视为继续领码；核实未发过码后按首码流程处理。
   - **明确向本活动求码，且未收到过码** → CSV 取首行码 → 发码并确认出现在右侧 → 从 CSV 删除该码行 → 距发码至少 2 秒后发送感谢语并验证。感谢语发送失败时单独记录，勿重发兑换码。
   - **>0 且曾发过码，对方最新消息表示码无效/被用过/兑换不了** → 补发：只发一条「给你换个新码：<CODE>」→ 验证 → 删行
   - **>0 且对方问怎么使用/怎么兑换** → 只发一条使用说明「<使用说明模板>」→ 验证（不发码、不改码表）
   - **致谢、表情、闲聊或无法确认与活动有关** → 跳过发送。回复失败或结果不明的会话要单独记录，下轮复核时不要只依赖未读角标。
3. 节奏：两条消息间隔 ≥2 秒，两个人间隔 ≥3 秒；每次运行最多处理 15 人。

### B. 新评论者引导

1. 打开笔记页，在评论区滚动容器内反复滚到底 + 点击所有「展开 N 条回复」，加载全部评论。
2. 提取评论**作者** uid（只取评论条目作者区域的链接，评论正文里的 @提及 不算作者），排除用户自己的 uid。
3. 与状态文件（见下）对比，新 uid 再核对会话列表：**有任何会话记录（含陌生人视图）= 已经私信过 = 跳过**；都没有的才需要评论引导。
4. 对每个目标（每轮最多 10 个）：找到其评论条目 → 点「回复」→ 输入框写引导语 → 点「发送」→ 验证该评论下出现用户自己的含引导语的子回复。两次评论回复的发送操作至少间隔 8 秒。
5. 成功的写入状态文件；失败/评论找不到的**不写入**（下次自动重试，这类用户的评论经常反复出现又消失）。

### 状态文件

记录已评论过的评论者 uid，防止重复评论。JSON 格式：

```json
{
  "noteId": "...",
  "authorUid": "自己的uid",
  "processedCommenters": ["uid1", "uid2"],
  "skipped": ["永久跳过的uid，如AI官方账号"]
}
```

首轮执行前创建，把当时已回复过的 uid 全部录入；之后每轮由脚本更新。

## 设置定时监控

用户要求定时运行且整套配置已齐备时，用环境提供的自动化入口注册（示例为每 30 分钟）：

```
title: 小红书<应用名>送码监控（每30分钟）
cron: */30 * * * *
prompt: 执行一轮小红书送码监控。笔记 <URL>；码表 <CSV路径>；感谢语「<模板>」；评论引导语「私我～」；问使用方法回复「<使用说明>」；状态文件 <路径>。流程：A 私信发码（陌生人折叠夹+主列表未读，逐条打开并当场处理核实后再开下一条，遇到问候、表情或「dd」先按账号核对目标笔记下的求码评论和作者引导，明确向本活动求码且未收过码→发码并验证、删行、再发感谢语，反馈失效→「给你换个新码：<CODE>」删行，问怎么使用→「<使用说明>」不改码表，普通聊天跳过标读）；B 新评论者（对比状态文件，无私信记录的评论「私我～」成功后更新状态文件）。防限流间隔、发送后必须验证、触发风控立即停止汇报；结束输出简报（处理人数/码号/CSV剩余<20提醒补充）；无新未读无新评论时简短回复。严禁重复感谢/重复评论/多发码/风控时继续操作。
```

用同一自动化入口调整频率、暂停或恢复。

## 规则与红线

- 发送后**必须验证**消息/评论真的出现了（检查 DOM），失败记录并跳过，绝不连续重试同一人
- 同一人只发一次首码；仅在确认先前的码失效时补发。发送结果不明时先保留该码并暂停发码，核对会话后再决定是否出库，避免同一码发给两人。感谢语不得重复发送
- CSV 只删已成功发送的行，删前后都 `wc -l` 核对，零残留
- 出现验证码/滑块/风控弹窗 → 立即停止本轮并汇报，等用户处理
- 未登录或登录过期 → 暂停操作，请用户在已打开的浏览器中自行登录；确认登录后继续。绝不索取账号凭据、读取 Cookie 或代替用户登录
- 跳过无诉求消息时顺便标记已读，避免每轮重复上报同样的人
