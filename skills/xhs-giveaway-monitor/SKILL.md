# 小红书送码监控

监控一篇小红书笔记的评论区 + 私信，自动完成「评论引导私信 → 私信发码 → 失效补码」的完整闭环。

## 前置条件

- 可访问小红书网页的内置浏览器。先检查现有登录态：已登录就直接复用；未登录或会话过期时，请用户在已打开的浏览器窗口中自行登录，然后继续。不要索取或读取用户密码、Cookie、会话令牌。
- 目标笔记 URL。先使用用户给出的链接或当前已打开的笔记页；如果裸链接触发 404/安全验证，请用户在已登录的浏览器中手动打开目标笔记。只有手动打开仍不可行时，才请用户补充含 `xsec_token` 的分享链接。
- 兑换码 CSV 文件：每行 `CODE,https://apps.apple.com/redeem?ctx=offercodes&id=<APPID>&code=CODE`。仅在用户明确要求自动发码且授权本轮发送后需要。
- 用户自己的小红书 uid 从已登录页面探测，不要要求用户提供。

用户只要求查看或监控时，默认只读检查并汇报；不得自行回复评论、发送私信或消耗兑换码。开始任何自动评论或私信前，确认用户明确授权了本轮发送，并取得所需 CSV 和消息模板。

## 需要向用户确认的参数

| 参数 | 说明 | 示例 |
|---|---|---|
| 码表 CSV 路径 | 仅自动发码时需要；每个码一行，从第一行顺序取 | `~/Downloads/表格/OfferCode_XXX.csv` |
| 感谢语模板 | 仅自动发码时需要，发码后紧跟着发送 | 原样发送，一字不改 |
| 评论引导语 | 仅自动回复评论时需要；默认 `私我～` | 可自定义 |
| 使用说明模板 | 仅自动回复兑换问题时需要 | `App Store 右上角头像点击，上拉找到兑换代码使用` |

笔记 URL 已由用户给出时，不再要求用户重复提供。需要自动发码时，如果用户尚未授权本轮发送或未提供码表、感谢语，则先向用户集中询问缺项；只读监控无需这些信息。

## 快速开始：执行一轮监控

一轮 = A 私信发码 + B 新评论者引导。按顺序执行，先读 references/tech-details.md 了解 DOM 结构和发送机制。

### A. 私信发码

1. 打开 `/chat` 页，检查「陌生人消息」折叠夹（未回复过的陌生人会被小红书折叠在这里，主列表看不到）和主列表中带未读角标的 c2c 会话。
2. 逐个打开未读会话，统计**用户自己发出的消息数**（右侧消息）：
   - **0 条**（从未回复）→ 新求码者：CSV 取首行码 → 发码 → 等 2 秒 → 发感谢语 → 两条都验证出现在右侧 → 从 CSV 删除该码行
   - **>0 且曾发过码，对方最新消息表示码无效/被用过/兑换不了** → 补发：只发一条「给你换个新码：<CODE>」→ 验证 → 删行
   - **>0 且对方问怎么使用/怎么兑换** → 只发一条使用说明「<使用说明模板>」→ 验证（不发码、不改码表）
   - **>0 且是致谢/表情/闲聊** → 跳过不发，可点开会话标记已读避免下轮重复上报
3. 节奏：两条消息间隔 ≥2 秒，两个人间隔 ≥3 秒；每次运行最多处理 15 人。

### B. 新评论者引导

1. 打开笔记页，在评论区滚动容器内反复滚到底 + 点击所有「展开 N 条回复」，加载全部评论。
2. 提取评论**作者** uid（只取评论条目作者区域的链接，评论正文里的 @提及 不算作者），排除用户自己的 uid。
3. 与状态文件（见下）对比，新 uid 再核对会话列表：**有任何会话记录（含陌生人视图）= 已经私信过 = 跳过**；都没有的才需要评论引导。
4. 对每个目标（每轮最多 10 个）：找到其评论条目 → 点「回复」→ 输入框写引导语 → 点「发送」→ 验证该评论下出现用户自己的含引导语的子回复 → 间隔 ≥6 秒。
5. 成功的写入状态文件；失败/评论找不到的**不写入**（下次自动重试，这类用户的评论经常反复出现又消失）。

### 状态文件

记录已评论过的评论者 uid，防止重复评论。JSON 格式：

```json
{
  "noteId": "...",
  "authorUid": "自己的uid",
  "processedCommenters": ["uid1", "uid2"],
  "skipped": ["永久跳过的uid，如AI官方账号"]
}
```

首轮执行前创建，把当时已回复过的 uid 全部录入；之后每轮由脚本更新。

## 设置定时监控

用户明确授权自动发送并确认所需参数后，用 CronCreate 注册（示例为每 30 分钟）：

```
title: 小红书<应用名>送码监控（每30分钟）
cron: */30 * * * *
prompt: 执行一轮小红书送码监控。笔记 <URL>；码表 <CSV路径>；感谢语「<模板>」；评论引导语「私我～」；问使用方法回复「<使用说明>」；状态文件 <路径>。流程：A 私信发码（陌生人折叠夹+主列表未读，0回复→发码+感谢语删行，反馈失效→「给你换个新码：<CODE>」删行，问怎么使用→「<使用说明>」不改码表，普通聊天跳过标读）；B 新评论者（对比状态文件，无私信记录的评论「私我～」成功后更新状态文件）。防限流间隔、发送后必须验证、触发风控立即停止汇报；结束输出简报（处理人数/码号/CSV剩余<20提醒补充）；无新未读无新评论时简短回复。严禁重复感谢/重复评论/多发码/风控时继续操作。
```

调整频率/暂停/恢复用 CronUpdate 改 cron 表达式即可，prompt 不变。

## 规则与红线

- 发送后**必须验证**消息/评论真的出现了（检查 DOM），失败记录并跳过，绝不连续重试同一人
- 同一人只发一次码；从不多发；感谢语绝不重发
- CSV 只删已成功发送的行，删前后都 `wc -l` 核对，零残留
- 出现验证码/滑块/风控弹窗 → 立即停止本轮并汇报，等用户处理
- 未登录或登录过期 → 暂停操作，请用户在已打开的浏览器中自行登录；确认登录后继续。绝不索取账号凭据、读取 Cookie 或代替用户登录
- 跳过无诉求消息时顺便标记已读，避免每轮重复上报同样的人
